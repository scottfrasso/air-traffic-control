# 2026-10-23: A second security review, and patching the MCP SDK

With a wave of critical vulnerabilities going around, we ran a fresh security review of the whole branch and audited
the dependencies.

**Dependencies.** `pnpm audit` found 11 advisories, 6 of them high, all in the Model Context Protocol SDK, which our
`/mcp` endpoint is built on (one could exhaust memory with a single request). The fix needed a small trick: the newest
`agents` release still pins the vulnerable SDK as a peer dependency, so we pinned the patched versions ourselves. Audit
clean, and a new test drives `/mcp` over real HTTP through the updated SDK, not just our tool functions.

**The review's best find: protected main had a back door.** Last week we made main move only by a merge: a direct push
gets put back. But a *merge* used whatever main was at that moment as its base. So: push unreviewed code to main, and
if anyone merges an approved PR before the guard notices, the merge commit has your code as its parent, and the guard
then protects *that*. A second way in: force-push an unrelated history after the container's cache went cold, and the
restore can't find the commit it should put back.

Fixes: a merge onto main now refuses unless main is exactly where the last merge left it; each merge also writes its
commit to a hidden ref, so a restore can always fetch it; and if a restore still fails, the repo freezes (no merges)
until a person puts main right.

The lesson for the post: a guard that *reacts* to bad state needs everything downstream to check the state too. The
merge was trusting main because "the guard handles that", and the guard was trusting time.
